# 👑 Gexatron: Цена Земли

**Gexatron: Цена Земли** — это многопользовательская (hot-seat) пошаговая стратегическая игра на Python с использованием библиотеки Pygame. Игрокам предстоит управлять экономикой изолированных провинций, расширять свои гексагональные территории, строить фермы и балансировать на грани банкротства, содержая мощную армию.

---

## 📊 Игровой баланс и Правила

### Экономическая модель объектов и Военных Юнитов (Units)
Каждая провинция имеет свой изолированный бюджет. Новое золото начисляется в начале каждого хода фракции по формуле:
`Баланс_Провинции = Доход_от_Земель + Доход_от_Ферм - Расход_на_Армию`

| Объект | Сила / Защита | Стоимость покупки | Стоимость за ход (содержание) | Защитный радиус |
| :--- | :---: | :---: | :---: | :---: |
| **Крестьянин (Peasant)** | 1 / 1 | 10 монет | 2 монеты | 0 клеток |
| **Копейщик (Spearman)** | 2 / 2 | 20 монет | 6 монет | 0 клеток |
| **Барон (Baron)** | 3 / 3 | 30 монет | 18 монет | 0 клеток |
| **Рыцарь (Knight)** | 4 / 3 | 40 монет | 36 монет | 0 клеток |
| **Домик (Ферма)** | 0 / 0 | 10 монет (+2 за каждую) | 0 монет | 0 клеток (приносит +4 золота) |
| **Башня (T2)** | 0 / 2 | 15 монет | 0 монет | 1 гексагон |
| **Сильная башня (T3)**| 0 / 3 | 35 монет | 0 монет | 1 гексагон |

### Ключевые условия и игровой процесс:
* **Прогрессивная стоимость ферм:** Базовая стоимость первой фермы составляет 10 монет. Каждая последующая ферма в этой провинции стоит на 2 монеты дороже предыдущей.
* **Тактическое слияние (Merge):** Игрок может переместить юнита на клетку с другим своим юнитом для повышения его тира (Крестьянин + Крестьянин = Копейщик). Максимальный юнит — Рыцарь.
* **Умный UX-помощник `(!)`:** Если в провинции текущего игрока есть доступные действия (юниты, которые еще не ходили, или золото на покупку минимального объекта), слева сверху от Капитолия этой земли отрисовывается восклицательный знак.
* **Банкротство (Голод):** Если в начале хода золото провинции уходит в минус, все боевые юниты в ней мгновенно погибают от голода, превращаясь в могилы. Казна сбрасывается в 0. Игрок не выбывает из игры, если у него остались земли.
* **Условие победы:** Контроль 100% обитаемых гексагонов на карте и полное уничтожение соперников.
* **Условие поражения:** Полное выбывание из hot-seat сессии наступает строго в тот момент, когда количество подконтрольных гексагонов становится равным 0.

## 🕹️ Управление в игре (Input Mapping)

Игра полностью адаптирована под управление мышью:
* **ЛКМ (Левая кнопка мыши):** Выбор гексагона, выбор провинции, покупка объектов в магазине HUD или выбор юнита для перемещения.
* **Перемещение / Атака:** Нажмите ЛКМ на своего активного юнита, затем нажмите ЛКМ на соседний гексагон. Если сила юнита строго выше защиты целевой клетки — она захватывается.
* **Слияние (Merge):** Нажмите ЛКМ на своего юнита, затем нажмите ЛКМ на клетку с другим своим юнитом для повышения его тира.
* **Завершение хода:** Нажатие кнопки **«Конец хода»** на панели HUD передает управление следующему игроку в режиме Hot-Seat.

## 🚀 Среда разработки и Запуск

### 1. Клонирование репозитория
```bash
git clone https://github.com
cd gexatron
```

### 2. Установка зависимостей и развертывание виртуального окружения
**Для CL-интерфейсов (Linux/macOS):**
```bash
python3 -m venv venv
source venv/bin/activate
pip install --upgrade pip
pip install pygame pytest pytest-cov
```

**Для Windows (PowerShell):**
```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install pygame pytest pytest-cov
```

### 3. Запуск приложения
> **⚠️ Важно:** Запуск основного скрипта должен производиться строго из корневой директории проекта, чтобы избежать сбоев относительных путей при загрузке статических ресурсов.
```bash
python main.py
```

### 4. Запуск тест-пакета
```bash
# Базовый запуск тестов бизнес-логики
pytest -v

# Запуск тестов в headless-окружении для CI/CD пайплайнов без X-сервера
# Linux/macOS:
SDL_VIDEODRIVER=dummy pytest -v
# Windows (PowerShell):
$env:SDL_VIDEODRIVER="dummy"; pytest -v
```

## 👥 Командная разработка и Распределение ролей

Проект реализован по методологии Agile (Scrum-спринты). Процесс разработки декомпозирован на 4 роли:

1. **Менеджер (Product Owner / Game Designer):** Спроектировал математическую модель прогрессивной стоимости ферм, боевые тиры юнитов и правила их содержания. Формализовал ТЗ на алгоритм связности провинций и визуальный индикатор активности `(!)`.
2. **UI/UX-Дизайнер:** Рассчитал математическую матрицу гексагональной сетки тайлов под экранное разрешение 1280×720. Создал цветовую палитру «Gexatron» для фракций и спроектировал оверлей интерфейса покупок и логов.
3. **Разработчик (Core Developer):** Написал ядро игры с четким разделением логики и рендеринга (Data/UI Separation). Реализовал алгоритм поиска в ширину (BFS) для динамического пересчета и дробления провинций при атаках соперников.
4. **Тестировщик (QA Engineer):** Покрыл автотестами (`pytest`) уязвимые участки кода: мерж юнитов выше допустимого тира Рыцаря, формулы баланса ферм и граничные условия голода армии при банкротстве провинции.
